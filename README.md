# Sales Dashboard IG — SaaS Analytics Dashboard

A premium analytics dashboard for an e-commerce business: revenue, customers, orders and products in one calm, fast workspace. Built with React 18, Vite, Tailwind CSS, React Router, Recharts and Framer Motion — with an optional real Node backend for genuine data persistence and real-time chat.

## Getting started

There are two ways to run this project. Both work; pick based on what you need.

### Option A — Quick preview (mock data, zero setup)

```bash
npm install
npm run dev       # http://localhost:5173
```

Everything works immediately: every button, form, export and page. Data lives in memory and is realistic and deterministic, but resets on a full page reload. Messages feel real-time through a built-in simulation (typing indicators, automatic replies, ambient activity) — good for demos, but it's one browser talking to itself.

### Option B — Real backend (real persistence + genuine real-time chat)

```bash
npm install
npm run dev:full   # starts the backend (port 4001) AND the frontend together
```

This runs an actual Node/Express server with a Socket.IO connection and saves data to `server/db.json` on disk — so it survives reloads and restarts. Messages sent from one browser tab/window are delivered to every other open tab **instantly over a real WebSocket**, not simulated. Open the app in two tabs (or two devices on the same network) and send a message in one — it appears in the other immediately, exactly like a real chat app.

To run the backend and frontend as separate processes instead (e.g. for deploying them separately):
```bash
npm run server     # backend only, http://localhost:4001
npm run dev        # in another terminal, with VITE_API_URL=http://localhost:4001/api in .env
```

Other scripts:
```bash
npm run build      # production build to dist/
npm run preview    # preview the production build locally
npm run lint       # ESLint
npm run format     # Prettier (writes)
npm test           # Vitest
```

Analytics and Reports are always generated by the same deterministic, seeded logic regardless of mode — they're synthetic data by design, so there's no separate backend route for them.

## Design direction

- **Palette:** neutral, cool-tinted greys with a single iris/indigo accent — not the generic "purple gradient SaaS" look. Full light and dark themes via CSS custom properties, with a smooth crossfade when toggling.
- **Typography:** Instrument Sans (UI/body) paired with Instrument Serif (page titles, card headers, modal titles, and the "Sales Dashboard IG" wordmark) for a distinctive, editorial, hand-crafted feel that carries through the whole app rather than just the homepage.
- **Charts:** a custom chart palette (`--c1`…`--c5`) shared by every Recharts chart and the product-category art, so data visualization stays consistent across the app.
- Every design choice — radii, shadows, spacing, iconography — is defined once as a token and reused, rather than picked per component.

If your browser is showing plain system fonts instead of the serif/sans pairing above, it's almost always one of: (1) `npm install` didn't fully complete (the two `@fontsource` packages need to download once, which needs internet access), or (2) the browser cached an old build — a hard refresh (Ctrl/Cmd+Shift+R) clears that.

│   ├── tables/                # DataTable + TableToolbar (sort, search, filter, paginate)
│   ├── cards/                 # KPI cards, activity feed, top products, quick actions
│   ├── layout/                 # AppLayout (shell), PageHeader, ErrorBoundary
│   ├── sidebar/ navbar/          # Navigation, search, notifications, theme switch, user menu
│   └── modals/                  # Command palette, confirm dialog, create/edit forms

├── hooks/                      # useAsync, useDebounce, useLocalStorage, useForm, useOverlay…

## Implemented pages

- **Dashboard** — KPI cards with sparklines, revenue/expenses/profit chart, sales trend, customer growth, top products, quick actions, recent activity.
- **Analytics** — filterable (channel/region/device/segment) traffic, conversion funnel, revenue by category and by country, all driven by the shared date-range picker.
- **Customers** — searchable, filterable, sortable table (including customers from Pakistan, India, UAE, and 15+ other countries); detail drawer with order history; add/edit/delete with validation and confirm dialogs; CSV export.
- **Orders** — table with status/payment filters, detail drawer with status actions (complete/cancel/refund), create-order flow with live totals, CSV and PDF export.
- **Products** — grid and list views, category art, stock badges, add/edit/delete, CSV export.
- **Reports** — generate a report by type and date range, preview on-screen, export CSV or PDF.
- **Messages** — real conversation threads with typing indicators and live delivery (see "Real-time chat" below), quick replies, responsive (list-only on mobile until a thread is opened), a settings shortcut to notification preferences.
- **Notifications** — filterable feed, mark read/unread, mark all read, dismiss, a settings shortcut.
- **Settings** — Profile (name, bio, a real photo upload, and a pickable avatar color — both reflected instantly in the navbar and everywhere else your avatar appears), Account (plan/usage/billing), Security (password, 2FA, sessions), Notification preferences, Appearance (light/dark/system), Integrations.
- **Profile** — summary card, weekly activity chart, recent activity.

## Key features

- Global command palette (⌘K / Ctrl+K) searching pages, customers, orders and products.
- Full light/dark/system theming with no flash-of-wrong-theme on load.
- Responsive throughout: collapsible sidebar → mobile drawer, tables that adapt, a two-pane inbox that collapses to one pane on small screens.
- **Real-time chat**: with the backend running (`npm run dev:full`), messages are delivered over a genuine WebSocket connection to every open tab/device the instant they're sent — this is real, not simulated. Without the backend (`npm run dev` alone), the same UI is driven by a local simulation (typing indicator, automatic replies, ambient activity) so it still feels alive with zero setup.
- **Real profile personalization**: upload an actual photo, or pick one of five accent colors for your initials avatar. Either way, the change is saved and shows up immediately in the navbar, the sidebar, and the Profile page — it isn't just a local form preview.
- Toasts, promise-based confirm dialogs, and focus-trapped modals/drawers (verified via automated keyboard-navigation testing).
- A real, dependency-free PDF generator (`src/utils/pdf.js`) for report and order exports — no external library needed.
- Optional real backend (`server/`) that mirrors the mock API's shape 1:1, so switching modes doesn't change how any page works — only where the data actually lives.
- Deterministic mock data (seeded PRNG) — realistic numbers that stay stable across reloads instead of re-randomizing.

## Verified during QA

- Production build succeeds; ESLint passes with 0 errors; Prettier-formatted throughout.
- Zero browser console/page errors across all pages, all Settings tabs, and a 404 route, in both themes and at mobile width.
- CSV exports open correctly (proper escaping, UTF-8 BOM for Excel) and the hand-rolled PDF export passes `qpdf --check` with no structural errors.
- Keyboard focus trap in modals verified (Tab cycles only within the open dialog).
- Real-time chat verified across two independent browser tabs against the real backend: a message (and its typing indicator) sent in one tab arrives in the other within milliseconds, with no duplication.
- Profile photo upload and avatar color changes verified to propagate live to the navbar avatar without a page reload.
- A handful of unit tests (`npm test`) cover the formatting and CSV-escaping utilities.

## Known limitations

- The backend (`server/`) is a genuine, working Node server, but it's meant to run locally next to the frontend for development/demo purposes — deploying it publicly would need basic hardening first (authentication on the API routes, rate limiting, a real database instead of a JSON file for concurrent-write safety).
- Authentication is not implemented; "Sign out" and password changes are demo-only in both modes.
- Analytics and Reports are always synthetic/deterministic (see above) — they don't reflect real customer/order/product edits you make, by design.
